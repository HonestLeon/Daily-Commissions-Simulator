# 删除「始终置顶」与「闹钟模式」——修改计划

> 状态：**已于 2026-10-23 按本计划实施完毕**（§8 三个取舍按默认选项执行：不留置顶开关、提醒彻底删除不发明替代、`Ctrl + Shift + T` 直接失效）。实施结果与真机待确认项见 `docs/代码审查报告-2026-10-21.md` §14。下文保留设计时的事实清点原样，行号是当时的基准。
> 触发需求：便签态的三种窗口模式（普通 / 始终置顶 / 闹钟）只保留「普通」，切换按键与设置里的闹钟间隔一并删干净。理由是桌宠态在不隐藏时本来就恒置顶。
> 行号基准：`src-tauri/src/lib.rs` 共 3371 行、45 个 `#[test]`；前端行号取自当前工作区。改动过程中行号会漂，落地时以**函数名/字符串**定位，别照抄行号。

## 1. 目标行为（先定契约，再动手）

| 形态        | 置顶                       | 说明                                                                                                                  |
| ----------- | -------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 便签态      | **不置顶**，且用户无法再改 | 三模式按钮删除后，普通态就是唯一形态                                                                                  |
| 桌宠态      | 恒置顶（隐藏时不算）       | 唯一实现点是 `noteStore.ts:367`（`collapseToPetForm()` 里 `setAlwaysOnTop(true)`），Rust 侧完全不碰 z-order，本次不动 |

### 2.3 置顶状态到底有没有被持久化（已查实：从来没有）

- `AppConfig` 里**没有** `pin_mode` 之类的字段；`pinMode` 只活在 Zustand（`noteStore.ts:458`，初值 `544`），boot 时靠 `App.tsx:119-129` 现读窗口状态反推。全仓 `src/` 无 `localStorage`/`sessionStorage` 使用。所以「模式选择」本身没有数据要迁移。
- **window-state 插件根本不持久化 z-order**——这不是本机没历史包袱的巧合，而是机制如此：`Cargo.lock` 钉定的 `tauri-plugin-window-state 2.4.1` 里 `StateFlags` 一共只有 6 个位（`SIZE/POSITION/MAXIMIZED/VISIBLE/DECORATIONS/FULLSCREEN`，源码 `…/src/lib.rs:50-59`），**不存在 `ALWAYS_ON_TOP`**；插件存档结构里也没有 `always_on_top` 字段，实测本机 `.window-state.json` 只有 `width/height/x/y/prev_x/prev_y/maximized/visible/decorated/fullscreen` 正是这个原因。当前 `lib.rs:3278-3294` 从 `all()` 里减掉 VISIBLE/SIZE/POSITION/MAXIMIZED/FULLSCREEN 之后，插件实际只记 `decorated`。
- ⇒ 结论比原稿更硬：**便签的置顶状态在磁盘上零足迹，老用户升级后必然从普通态起步，不存在任何迁移/残留问题**。代码侧唯一要做的是 §3.1 把 `expandToNoteForm` 改成无条件 `setAlwaysOnTop(false)`，从此连「启动瞬间被上次会话带成置顶」的理论窗口都不存在。

## 6. 连带影响与风险

1. **闹钟是 JS 侧「隐藏到托盘 + `setMediaPaused(true)`」的调用者之一**。删掉后仍会 hide 窗口的只剩桌宠避让（`setPetAvoided` `937-939`）和气泡（`PetBubble.tsx:47`）。`mediaPaused` 的生产/消费链（`pet-visibility-changed` 广播、`App.syncVisibility`、`PetStage` 挂载与 unpause 分支）都还有别的调用者，不会变死代码；但有两处**中文注释**会因为闹钟消失而悬空，编译与测试都抓不到，只能靠人过一遍：`PetStage.tsx:224`「隐藏启动（托盘）」应改成「避让 / 托盘隐藏」；`noteStore.ts:517-521` `mediaPaused` 的 docstring 把「闹钟收尾」列为隐藏路径之一（已写进 §3.1 的改动项）。
2. **闹钟到点把宠物撑回便签**这个 ⚠ 偏差（`docs/桌宠化重构计划.md:179-190`）随闹钟一起消失，是净收益。
3. **提醒能力没有替代品**。闹钟是唯一的自动提醒；删了之后只剩桌宠气泡 `say()`（且只在主人空闲 8~600 s 才开口）。本次按「彻底删除」执行，不顺手发明替代特性。
4. **老用户正处于 pin/alarm 的唯一可见变化**：便签不再置顶、不再定时弹提醒。模式选择不落盘（§2.3），所以不存在配置迁移问题。
5. **托盘的意义进一步缩小**：关闭即退出（上一轮）+ 闹钟消失后，托盘只剩「主动隐藏时唤回、切桌宠、切自启、退出」。本次不动托盘；但 `App.tsx:132-133` 那条注释「应用可能作为托盘常驻运行好几天：跨过午夜后要自己结算昨天、创建今天」的前提变弱（这句话在**代码注释**里，AGENTS.md 没有它）——**跨日巡检代码不要顺手删**（窗口长开不关的场景仍然成立，注释本身可择机改成「窗口长期开着」的口吻）。
6. **`expandToNoteForm` 少一个形参**后，别试图从 store 猜「便签要不要置顶」——store 里已经没有 pinMode。
7. **`Ctrl + Shift + T` 删除后文档快捷键表必须同步**，否则用户按下无反应会当成 bug。
8. **不升版本号、不重打发布包**（用户没要求）。若要进下一版发布，版本号四处一致由用户单独点头。
