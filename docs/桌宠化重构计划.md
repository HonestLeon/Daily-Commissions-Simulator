## 1. 目标形态定义

```
                 ┌──────────────────────────────────────────┐
                 │ pet（桌宠态）                             │
                 │ 窗口 = 精灵可见包围盒 ≈ 175×220           │
                 │ alwaysOnTop=true  focusable=false         │
                 │ 内容：PetStage(<video>)，气泡另开小窗      │
                 └───────┬───────────────────────▲──────────┘
        单击精灵 | 托盘「展开便签」                | pointerleave + 宽限期
                                                  | 且 无焦点/无未保存改动
                 ┌───────▼───────────────────────┴──────────┐
                 │ note（便签态）= 今天的全部功能，不变      │
                 │ 窗口 = 现有 620×500（可拉伸）             │
                 │ alwaysOnTop=按 pinMode  focusable=true    │
                 └───────────────────────────────────────────┘
```

- **形态是 UI 层的视图状态，不是新的数据实体**。委托内容、结算、余额在两种形态下完全同源。
- 新增一个总开关 `petEnabled`（**目前只有托盘菜单能开；设置面板分区是 PR8**），关掉后应用行为与今天 100% 一致——**这是回滚保险**：桌宠化全部改动都必须在 `petEnabled=false` 路径上零影响。
- **气泡走独立小窗（默认），合并包围盒只是退路**（已实现，风险仍待验）。原则 3 在这里必须赢：气泡挂在精灵上方时，「精灵 ∪ 气泡」的合并包围盒**中间必然夹着一块透明区**，而我们在 Tauri/WebView2 上拿不到逐像素点穿（调研 §2.3.3 / §5.1）——那块透明区就是一块点不动桌面的死区，正好撞上原则 3 禁止的东西。所以：**主方案 = 紧贴文字尺寸的独立 `bubble` 小窗**（调研 §2.3.3 的结论，PR6 已落地）；**退路 = 合并包围盒**，仅在独立小窗实测出问题（§2 问题 7、§9 风险 11）时启用。
  - 这不违反原则 1：「单窗两态」约束的是**便签态 ⇄ 宠物态**这两个主形态（编辑器 DOM 必须活在同一条 webview 里），一个纯展示、无输入、随文字收紧的气泡辅助窗不在其列。
  - 实现约定：`bubble` 窗在 `tauri.conf.json` 里**静态声明**（`transparent:true`、`decorations:false`、`focusable:false`、`skipTaskbar:true`、`alwaysOnTop:true`、`visible:false`、`resizable:false`），尺寸与位置由代码算；前端**用 `getCurrentWindow().label` 分流渲染**，不拿 URL query 当路由；`capabilities/default.json` 的 `windows` 数组必须加上 `"bubble"`（AGENTS.md 契约：不在里面 = 核心 API 静默不可用）。
  - 几何照抄 `CompanionEdgeLayout.Follow`：按实测文字盒紧收敛（`MaxWidth ≤ 300`，并预留 2 px 防换行算少一行）、优先放精灵**上方**、放不下翻**下方**、始终钳在工作区内、尖角指向头部。
  - 代价要如实记着：多一个 WebView2 窗 = 多一份内存 + 一次「隐藏透明窗首显」的风险（§9 风险 11），换来的是宠物态主窗保持最小、桌面死区最小。

### 明确不做

Live2D / Rive、分区点击穿透、全屏透明覆盖层、宠物自主跑动（`FramePresented` 插值那套，`<video>` 无等价回调）、内置 AI/LLM、多宠物注册表（M3 之前）。

## 3. 数据与跨层契约变更

### 3.1 `AppConfig` 新字段（`src-tauri/src/lib.rs:651`）

沿用现有风格：`#[serde(default)]` + `Default::default()`（`:747`）+ 读取时 `normalize_*` 纠偏（`normalize_alarm_config` `:831`、`normalize_theme` `:848`、新增 `normalize_pet_config` `:814`，都挂在 `load_config`（`:783`）里）。

实际落地的字段（`lib.rs:675-708`，命名与本计划早前一版有两处出入：`pet_action_index` 而非 `pet_action_minutes_index`；`form` 提到 `pet_enabled` 之后）：

```
pet_enabled: bool = false          // 总开关，默认关（回滚保险）
form: String = "note"              // "pet" | "note"，上次退出时的形态（APP_FORMS 白名单）
pet_scale: f32 = 1.0               // PET_SCALE_MIN 0.5 – PET_SCALE_MAX 1.5，clamp
pet_action_index: u8 = 2           // PET_ACTION_RANGES 六档下标：(15,30)(30,60)(45,90)(60,120)(120,180)(180,300)
pet_auto_collapse_ms: u32 = 500    // 0 = 不自动缩回；超 PET_COLLAPSE_MS_MAX 5000 回默认
pet_hide_on_fullscreen: bool = true
pet_x / pet_y: Option<i32>         // 宠物态只存位置——尺寸永远由 175×221 × scale × scaleFactor 算出来
note_x / note_y: Option<i32>       // 便签态存全套
note_w / note_h: Option<u32>
```

> 全部给 `#[serde(default)]`，老用户 `config.json` 缺字段不会崩；`normalize_pet_config()`（`lib.rs:814`）做 clamp，非法值静默纠偏（抄调研 §2.3.6-4）。
> 几何读写不是前端直接 `save_config`，而是走 `get_ui_state` / `save_ui_state` 两个新命令，`UiState` 一次把开关、scale、区间、宽限、避让、两套几何打包传回，前端 `fetchUiState()` 启动时读一次、`autosaveGeometry()` 在 `onMoved/onResized` 去抖 400 ms 后写一次。Rust 侧 `apply_ui_state()` 负责「宠物态只落位置、便签态落全套」这条不对称。

> **为什么 `pet_scale` 上限收在 1.5 而不是照抄大肥鱼的 2.0**：宠物盒是可见包围盒，代码里的基准是 **175×221**（`PET_BOX_W/H`，按调研 §2.3.3 的 `220:278` 比例、对应 640×360 素材框算出）。于是 Scale 1.0 → 175×221，1.3 → 约 228×287，**1.5 → 约 263×332，2.0 → 约 350×442**。我们做不到逐像素点穿（§1 原则 3），所以 Scale 直接等于「桌面死区」的尺寸：2.0 会在桌面上吃掉一块 350×442 的不可点区域，比黑屏更要命。**这条上限不是像素硬编码，而是「实测通过前不放开」**：§2 问题 5/6 实测确认无黑屏、死区可接受后，若要把上限放回 2.0，改 `PET_SCALE_MAX` 这一处即可（想更保守可先收 1.3）。同时修正本文早前一版把「≤240×280」当成 Win10 黑屏硬上限的说法——那个数字没有依据：现有便签态本身就是 620×500 透明窗且运行正常，#15947 的触发条件是**高频 `setIgnoreCursorEvents` 与最小化时的 DWM 竞争**（调研 §5.2），不是绝对尺寸。

### 3.2 `save_config` 改原子写（已完成，`src-tauri/src/lib.rs:863`）

原来是裸 `fs::write`——崩在半路就把用户配置写坏，而桌宠化之后 `config.json` 还要多存几何与开关，风险面变大。现在是 `write_config_atomic()`：写 `config.json.tmp` → `sync_all()` → 把旧文件改名成 `config.json.bak` → 把 tmp 改名成正式文件；读取走 `read_config_file()`（`:797`），`config.json` 解析失败就退 `.bak`，再退 `Default::default()`。`cargo test` 里 `write_config_atomic_keeps_previous_generation` 断言「写完两代之后 `.bak` 仍是上一代内容」。

### 3.3 `window-state` 剔除 SIZE / POSITION（已完成，`src-tauri/src/lib.rs:2337-2340`）

原来只排除了 `VISIBLE`。若不处理，**退出时处于宠物态 → 下次启动是一个被 `minWidth` 夹住的畸形小窗**（调研 §5.4）。现在是：

```rust
tauri_plugin_window_state::StateFlags::all()
    & !StateFlags::VISIBLE
    & !StateFlags::SIZE
    & !StateFlags::POSITION
```

几何完全由 §3.1 的两套字段负责。**注意与计划不同的一点**：落位不在 Rust 的 `setup()` 里做，而是前端 `fetchUiState()` 拿到 `form` 后由 `setForm` 走一次完整时序（宠物态启动 → 直接是宠物盒）。原因是形态切换的时序（`setMinSize` → `setSize` → `setFocusable`）本来就只打算有一份实现，Rust 侧再写一遍必然漂移。代价是启动时会有一次「窗口先按 `tauri.conf.json` 尺寸出现、随后被缩到宠物盒」的可见跳变——**待验**，若实测难看，就在 `setup()` 里按 `form` 预置初始 `width/height`，把跳变压到首帧之前。

### 3.4 新增 Rust 命令

## 4. 形态切换的时序（已落地为 `noteStore.ts` 的两个私有函数）

```
展开（pet → note）＝ expandToNoteForm(geom, pinMode)
  1. setFocusable(true)                      // 先给焦点能力，否则编辑器不能打字
  2. setMinSize(LogicalSize(340, 300))       // 恢复便签下限（对应 tauri.conf.json:20-21）
  3. setSize + setPosition（按物理像素存档、按 scaleFactor 换算、钳进所在 monitor 工作区）
  4. setAlwaysOnTop(pinMode === "pin")       // 便签态不再无条件置顶
  5. 窗口落位之后才 set({form:"note"}) + applyFormMarker

缩回（note → pet）＝ collapseToPetForm(petPos, scale)
  1. 门禁：hasPendingEdit（500 ms 自动保存还没落地）或 editorBusy()（焦点在 .ProseMirror 里）→ **直接拒绝缩回**
  2. 先换成宠物内容 + applyFormMarker("pet")，sleep 60 ms 让 DOM 换完
  3. setMinSize(null) → setSize(175×221 × scale × sf) → setPosition（有存档用存档，否则贴便签窗下沿一角）→ snapToWorkArea（14 px 吸附）
  4. setAlwaysOnTop(true)
  5. setFocusable(false)                     // 最后一步，防止中途丢事件
  6. readWindowGeometry() 读回**真实**几何再 persistFormGeometry，不记「打算设成多少」
```

- 入口只有 `useNoteStore.setForm(next)` 一个：`formBusy` 互斥锁拒绝并发（并发会把 `setFocusable`/`setMinSize` 配成对错），`petEnabled === false` 时**任何请求都被折回 `"note"`**，异常走 `finally` 释放锁。组件里没有任何一处自己 `setSize`。
- **与计划的偏差**：原写「先 flush 未保存编辑再缩回」，实现改成了**有未保存改动就拒绝缩回**（更保守，也不会把半截内容写盘）。CSS 侧也不用「动画结束后再 resize」，而是「内容换完隔 60 ms（`PET_SWAP_MS`）再 resize」——顺序反了会带着便签布局去 resize。
- **单击 vs 拖拽**（调研 §2.3.4，已实现于 `PetStage.tsx`）：`pointerdown` 记 `e.screenX/Y`，`pointerup` 时 `|dx|+|dy| > 4` 判为拖拽（走 `startDragging()`），否则判为单击展开。宠物态**不能**整窗挂 `data-tauri-drag-region`——现有标题栏就是这么做的（`src/components/TitleBar.tsx:78`，并在 `:80` 判 `e.target`）。
- **屏幕钳制按可见内容**而非窗口矩形，并 14 px 内吸附到工作区边（`CompanionEdgeLayout.Clamp` 的思路）。用 `monitorFromPoint()`（`window.d.ts:1828`）与 `availableMonitors()`；物理/逻辑像素的换算在 `clampToWorkArea` / `snapToWorkArea` 里显式做，几何**永远以物理像素存**。
- **`--startup` 冷启动**：**仍未做，属 PR7 之后的行为变更**。现在开机自启仍是「不 `show()`，留在托盘」（`cfg(debug_assertions)` 下自启本身被拒，AGENTS.md）。加了 `form` 之后，`--startup` + `form="pet"` 时应直接以宠物态显示——**这是行为变更，要单列并在 README 更新日志里写清**，且验收只能在发布版做。

现有 `PinMode`（`types/index.ts:14`）三态 + 闹钟定时器（`stopAlarmTimer`/`startAlarmTimer`，`noteStore.ts:215-275`，会 `show()` + `setAlwaysOnTop(true)` + 到期 `hide()`/`minimize()`）已经在操作同一个窗口。桌宠态加入后必须定死优先级：

## 6. 动作与气泡的领域模型（用我们的数据替掉它的 LLM）

调研 §2.3.5 已证「动画与 AI 无关」。它那份 `animations.json` 的结构可直接照抄，字段砍到我们需要的：

```jsonc
// src/assets/pet/pet_actions.json（已落地 12 条；File 写 ASCII 主干名，不含扩展名）
{ "Id": "待机呼吸休闲", "File": "idle-breath", "Pool": "Idle", "Weight": 100 }
{ "Id": "原地小憩沉眠", "File": "idle-sleep", "Pool": "Idle", "Weight": 240, "HourFrom": 23, "HourTo": 8 }
{ "Id": "工作状态-垂头叹气冒汗", "File": "mood-sulk", "Pool": "Idle", "Weight": 300, "Gate": "incomplete" }
{ "Id": "余额-金袋叮当", "File": "mood-coins", "Pool": "Notify", "Weight": 100, "Gate": "settled" }
```

- **池**（实际五类，`PetPool`）：`Idle`（轮换充当循环，无需首尾相接）/ `Click` / `Drag` / `Greeting`（每次进入宠物态播一次 `greet-bow`）/ `Daily`（时段事件，`daily-brush` 每天只播一次）/ `Notify`（数据事件）。**计划里的 `Farewell`（退出）没做**——退出时窗已经没了，播给谁看；它的 `Meal/Festival/Season` 依旧不抄（§9 不抄）。
- **`Gate` 条件项**（实际四个，`PetGate`）：`triple` / `incomplete`（有真委托但未三全）/ `empty_note`（明日委托没填）/ `settled`（`settledAt` 三分钟内）。全部由 Rust 的 `get_today_progress` + 前端记住的 `settledAt` 算出（`computePetGates`），**前端不自己数勾选框**。`yuanShi`/`mora` 当次增量、`streak` 这两个字段暂时没接进 Gate：结算气泡已经用 `say()` 直接报数，动作侧再用一次增量收益不大。
- **时段判定**：`hourMatches` 里 23→8 这种跨午夜区间按「晚于起 **或** 早于止」命中，不用 `&&`。
- **空闲门控**（PR7 已做）：`say()` 开口前读 `get_idle_seconds`，只在 **8–600 s** 这段窗口期说；`< 8 s` 每 5 s 复检一次、最长攒 3 分钟后作废，`> 600 s` 直接不说（人走了）。同时 `mediaPaused`（隐藏到托盘 / 避让全屏）时**整条丢弃**，宠物看不见就不说话。读不到空闲值（非 Tauri / 命令失败）就**不门控**，避免把话憋死。**只门控气泡**：`App.tsx` 里两处 `say()` 都在 `form === "pet"` 分支内，所以 `petEnabled=false` 的用户完全不受影响。
- **可见性与解码**（PR7 已做）：Rust 侧所有 hide/show 都收敛到 `hide_main_to_tray` / `reveal_main` 两个函数，它们广播 `pet-visibility-changed`（bool）；前端据此置 `mediaPaused`，`PetStage` 在真正的可见性翻转时 `pause()` 两层 `<video>` + 作废在途回调（`generation += 1`）+ 停掉调度定时器，恢复时 `play()` 当前层并重新排程。store 自己的 hide（闹钟收尾隐藏）与避让也各自置位，挂载那一趟仍交给入场 effect，避免两条 effect 抢画面。
- **调度**：**没有 40 ms tick**。`PetStage.armTimer()` 直接 `setTimeout` 到 `petActionMinSec…petActionMaxSec` 之间的随机秒数（六档区间来自 Rust `PET_ACTION_RANGES`），动作播完按 `onActionEnded` 决定是否串下一个。理由：我们只有 `<video>`，不需要逐帧插值，常驻 tick 白白让 webview 保持活跃。隐藏时的暂停见上一条「可见性与解码」。
- **取消语义**：两处都是单调版本号（`PetStage` 的 `generation`、`PetBubble` 的 `version`），打断源自增，迟到的 `onended`/`setTimeout` 回调按版本号作废。这是它踩过的坑，我们直接抄。
- **构建期校验**：**换了写法**。不用 `import.meta.glob`，而是在 `petAnimations.ts` 里逐个静态 `import url from "../assets/pet/*.webm"` 拼成 `URLS` 表，清单里的 `File` 查不到就 `console.error` 并丢弃该条。静态 import 的效果更强：素材文件缺失或改名会让 `npm run build` 直接失败（`import.meta.glob` 只会静默给空对象）；清单写了不存在的**条目**不会崩构建，而是运行时退色块。加载失败退化：`readyState>=2` 才交叉淡入 + 2500 ms 看门狗 + `onError` → `broken` → CSS 色块呼吸，绝不留空白窗。
