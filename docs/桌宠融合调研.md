#### 2.3.2 动画管线：本次最关键的发现

- 它**不用** `MediaElement`（全仓零命中）。每段动作起一个 `media/ffmpeg.exe` 子进程：`-threads 1 -c:v libvpx-vp9 -i x.webm -an -sn -f rawvideo -pix_fmt bgra pipe:1`，每帧 921,600 B 喂给常驻的 `WriteableBitmap.WritePixels`，用 `Stopwatch + Task.Delay(5)` 按 24fps 节流（`CompanionVideoPlayer.cs`）。
- 为什么它必须自己解码：需要 (a) `a<8 → 0` 的像素级键控（保分层窗口点击穿透）、(b) `HitTestCore` 逐像素 alpha≥16 命中、(c) `FramePresented` 帧级回调给「奔跑」插值位移、(d) 可暂停 / 可节流的时钟。`MediaElement` 四项全不给。**这三条 (a)(b)(c) 恰好都是 WPF 专有能力，我们在 Tauri 上本来也拿不到**——所以不必遗憾。
- **我们不需要复刻这条链**：WebView2 就是 Chromium，`<video>` 原生支持带 alpha 的 VP9 WebM。两级实测：
  - **素材侧**（本机 `imageio-ffmpeg` 7.1 解码 `待机呼吸休闲.webm` 第 48 帧）→ `mode RGBA`、`alpha extrema (0,255)`；容器内有 `AlphaMode` 元素，编码 `V_VP9` / `Lavc63.1.101 libvpx-vp9`。
  - **渲染侧（本机 Edge 无头截图；Chromium 与 WebView2 同引擎）**：把该 webm 放进 `background:#f0f` 的页面里 `<video muted autoplay playsinline>`，`--headless=new --screenshot` 取回的图中，视频框 640×360 内**四周是纯洋红**（透明区正确透出页面背景），角色像素 38,781 个、包围盒 **x213–425 / y64–329**，与它代码里写死的可见身体区 `208–428 / 58–336` 对得上；无 video 的空白对照页中心为 `(255,0,255)`。**→ `<video>` 直接播即可，alpha 真实生效。**
  - 由此**省掉整个 ffmpeg 子进程、Job Object 防孤儿、22.1 MB/s 裸帧带宽**——它的桌宠外壳里最复杂的那块工程，对我们来说是一条 `<video>` 标签。
- 防闪烁：`Play()` 先 `Stop()`（`generation++` 杀旧进程），但位图仍显示上一段最后一帧，新段第一帧原地覆写，不留空白帧。我们用 `<video>` 的等价做法是两个 `<video>` 交替（或先 `load()` 到离屏元素、等 `canplay` 再切可见层），别直接换 `src` 后干等。
- **不做无缝循环**：只在整段边界决定下一动作，靠 `Idle` 池轮换充当「循环」。这对我们是好消息——10 s 一段的素材不需要首尾相接，素材生产难度大幅下降。
- 省资源三招：`-threads 1`、只允许一帧在飞、隐藏或被全屏挤走时 `Paused = true` 直接停表（`CompanionWindow.cs:606`）。我们用 `<video>` 时对应 `pause()` + `src=''`，**别忘了显式 pause**，否则 24fps 解码会在托盘隐藏期间继续烧 CPU。

#### 2.3.3 窗口几何，以及「透明处能点穿」的真相

- 尺寸公式（`CompanionWindow.cs:48`、`:292-305`）：`SpriteSize = 280 × Scale`（Scale 0.5–2.0 可调），`Width = SpriteSize*640/360 + 20`、`Height = SpriteSize + 35` → Scale=1 时窗口约 **518×315**。
- 可见身体区（`CompanionAnimations.cs:40-43`）：`220/360 × 278/360` 的 `SpriteSize` → Scale=1 时约 **171×216**，只占窗口面积 ~37%。其余 63% 透明留白是留给气泡、跑动位移和贴边用的。
- ⚠ 那 63% 透明区**在它的平台上不挡点击**，靠的是 `WS_EX_LAYERED` 分层窗口的逐像素 alpha 命中，外加两处刻意强化：解码后 `if (a < 8) a = 0`（清 VP9 alpha 的压缩残值，代码注释明写是为了「保证分层窗口在角色周围保持点击穿透」）与 `CompanionSpriteImage.HitTestCore` 的 `pixel[3] >= 16`。**Tauri/WebView2 复制不了这条**（§5.1），所以我们只能走「窗口收到包围盒本身」。
- **对本文的直接修正**：§8 M0 原假设宠物态 **96×96**，采用这套 640×360 素材就不成立——紧贴包围盒应是 **≈175×220**（Scale=1）或 **≈90×115**（Scale=0.5）。宽高比 220:278 ≈ 0.79，**不是正方形**。
- 边缘停靠做得很细（`CompanionEdgeLayout.Clamp`，:244-274）：钳制的是**可见身体**而非窗口矩形（`left` 允许到 `area.Left - petBounds.Left`，即透明留白可以出屏），并在 **14 px 内吸附**到工作区边。「按可见内容而非窗口矩形做钳制」这条必须照搬，否则每次 resize 角色都会钻出屏幕。
- **气泡是独立的第二个顶层窗**（`CompanionEdgeLayout.Follow`，:97-208）：把 `bubble` 从主窗 `Children` 里摘走，塞进另一个透明 / 置顶 / 不抢焦点的 popup 窗，**按文字实测尺寸紧收敛**（`MaxWidth ≤ 300`、还预留 2 DIP 防止换行边界算少一行），优先放宠物**上方**、放不下翻到**下方**、始终钳在工作区内、尖角 `PointAt()` 跟着指向头部。
  → 这条证据**给 §6 的二分法打了个补丁**：「单窗两态」对便签面板仍然成立（编辑器 DOM 必须存活），但**临时性小气泡更适合另开一个紧贴文字的小窗**——它不违反「别销毁编辑器」，又能让宠物态主窗保持最小尺寸。

#### 2.3.5 AI 耦合度：确认「可以只要外壳」

- **动画完全不由 AI 驱动**：`CompanionAnimationPolicy.cs:37` 注释直说 "Pure policy… never capture the screen or invoke a model"；106 条规则按季节 / 农历节日（含闰月）/ 餐点 / 时辰奇偶 / 早晚加权随机，由 `nextAction` 定时器（默认 40 s，30–300 s 可调）驱动。
- 气泡有**三条独立通道**：模型流式（`ShowCompanionPartial`）、**非 AI 固定文案**（`ShowCompanionNotice`：启动请安 / 道别 / 离电提示 / 动画加载失败）、外部原文（MCP `ShowMcpSpeech`）。`bubbleIsModelReply` 只用来区分「谁有资格被覆盖」。
- 官方明确保证「无模型模式」：README:77 ——「她依然会行礼、问候、道别，播放全部动作表情，回应主人的点击和拖动」。
- 耦合点集中在 12 处单向调用（`CompanionWindow.cs:68/479/577-587/594/611-612/651/716-719` 等），全是「门禁 + 生成 + 取消」，外壳不被 AI 反向依赖。
- **结论：容易偏中等。** 删 `Brain/Dialogue/Ocr/OcrLayout/ScreenCapture/News/Weather`（约 1734 行）+ 摘掉 6 处门禁与 loading-ring 调用即可；动画、拖拽、边缘停靠、气泡逐字、托盘、菜单、全屏隐藏、偏好持久化零改动。唯一真实工作量是**自建句池**——它的固定文案不足 10 条且**没有本地随机文案池**（`CompanionDialogue.cs:26` 的 `Reactions[]` 是给 LLM 的 prompt，不是显示文本）。而这恰好是我们天然更强的地方：我们有真实数据（原石 / 摩拉 / 砺行连续周数 / 三模块完成度 / 明日委托是否已填），文案由数据生成，不需要 LLM。
- **不要连带搬过来的**：2.7 GB 模型、`llama-server` 子进程、GPU→CPU 自动降级、离电移出内存（它做「离电暂停」纯粹因为模型 resident 太吃笔记本续航：`WM_POWERBROADCAST 0x218` + `GetSystemPowerStatus`，真 `Kill` 进程树）。这些复杂度全部是我们的负担，不是收益。

#### 2.3.6 与桌宠形态无关、但值得直接抄的工程做法

1. **PS 脚本编码硬闸门**：`code/tests/PowerShellEncodingVerification.ps1` **只有 13 行**——`git ls-files '*.ps1'` 逐个断言首三字节 `239,187,191`，再用 `[Management.Automation.Language.Parser]::ParseFile` 断言零语法错误，并排在 `test.ps1` 第一步；CHANGELOG 1.0.1 专门记了这条修复。→ 正中 AGENTS.md 记录的 `build-release.ps1` 必须 UTF-8 BOM 这个坑（现仅靠 Stop hook 提示、不阻断）。可并进 `.qoder/hooks/check.sh` 做成硬失败。
2. **版本单点 + 产物回读核对**：根 `Version.props` 被 `Directory.Build.props` import，installer / uninstaller / Mcp 都由此生成版本；PS 侧 `Get-ProjectVersion.ps1` 用 `[xml]` 解析同一文件并校验三段数字格式，`Build-LocalVariant.ps1:13-14` **构建完从 exe 的 `VersionInfo` 把版本读回来反向核对**。→ 我们四处版本号（`package.json` / `Cargo.toml` / `tauri.conf.json` / README）目前只做静态 grep，补一条「`tauri build` 后读 exe 的 ProductVersion 与 `package.json` 比」就能把「改了配置没改文档」从人工纪律变成构建期失败。
3. **自更新三件套（我们现在基本没有）**：`.partial` + `Range` 断点续传 + 整文件 SHA256，已完成的目标文件先 hash 命中即跳过（`deployment/ArtifactDownload.cs`）；升级事务 `moving/installing/committed` 三阶段日志 + 旧文件**移走**而非复制 + `LaunchAndVerify` 要求新版写出 `ready.status` 且进程存活才算成功、否则杀进程回滚旧版（`installer/UpdateTransaction.cs`、`installer/Program.cs:148-166`）；`Preserved()` 白名单保证升级永不覆盖 `models/cache/preferences`；还有 `--wait-pid`（等应用自己正常退出，不硬 Kill）。→ 我们目前是「下载安装包 → 装了打不开就自求多福」。Tauri 侧落地点极便宜：数据目录里由 `setup()` 末尾 touch 一个 `ready.status`，更新脚本 / 下一实例读它判活。
4. **偏好文件原子写 + 读时纠偏**：写 `tmp` → `File.Replace(→ .bak)`，读失败退 `.bak` 再退全新默认；默认值直接写在属性初始值上（**无 schema、无迁移表**），读取时**逐字段 `Math.Clamp`**（Scale 0.5–2、动作间隔 30–300、三餐小时 0–23、气泡档位、地区码归默认），非法值静默纠偏而不是崩（`CompanionPreferences.cs:71-118`）。→ 对 `config.json` 最值得抄：我们现在的透明度 / 主题 / 提醒间隔等字段一旦被手改成非法值，行为取决于下游运气。
5. **验证程序的形态**：`code/tests/*Verification` 每个是一个独立 csproj 控制台程序，统一模式 `Check(bool, string)` → 计数 → `RESULT n checks passed` → 非零退出码。三种玩法：注入假 `HttpMessageHandler` 断纯逻辑 / **真 WPF 实窗**（反射读写私有字段、对真按钮 `RaiseEvent`、`Dispatcher.PushFrame` 泵消息、`RenderTargetBitmap` 存 PNG 供肉眼核对、断言控件几何不越界）/ 跨进程 UI Automation + `CreateRestrictedToken` 降权真跑安装器。沙箱化很便宜：`test.ps1:8-14` 用 **NTFS Junction** 把已装的 assets/runtime 接进 `.verification/`，不复制 2.7 GB、不碰真用户数据。→ 这套适合「一人维护 + 发版前手动跑一遍」，与我们「tsc 即闸门」的定位一致，不必整体照搬；对我们最有性价比的是「**断言几何不越界 + 存 PNG 肉眼看**」这类回归，恰好是桌宠形态切换最需要的。

## 3. 交互范式归纳

调研到的「宠物 ⇄ 面板」切换共四种主流做法，本项目需要的是第 1 + 第 2 种的组合：

1. **点击展开**（LingoPet 右键面板、小美同学双击）—— 单击宠物本体 → 面板出现；这是用户构想的默认路径。
2. **悬停展开 / 移开收起**（DeskBox 胶囊模式）—— 用户构想的收起路径。关键细节：**都要有可配置的宽限期**，无宽限的实现在实践中被认为难以使用（鼠标穿过缝隙、滚动、去面板边缘都会误收起）。
3. **边缘吸附成标签**（小美同学、多数 shimeji）—— 拖到屏幕边缘只留一条边签，作为「宠物太大挡路」的退路。
4. **常驻不动、气泡承载信息**（LingPal、Clawd-on-desk）—— 宠物不展开面板，信息以气泡/动作呈现，适合做「结算完成」「新一天提醒」这类轻提示。

## 5. 硬约束与已知坑（逐条给对策）

### 5.1 分区点击穿透：官方不做

[issue #13070](https://github.com/tauri-apps/tauri/issues/13070) —— 透明窗口只支持**整窗** `setIgnoreCursorEvents`，官方回复 _"This won't be implemented"_，社区 workaround 是「自己做 hitbox 探测，再整窗 toggle」。

**对策**：

- 宠物态窗口尺寸**紧贴精灵的实际不透明包围盒**，绝不留大片透明区域（色块占位期可用 120×150；α-WebM 素材 Scale=1 约 175×220，见 §2.3.3）；
- **禁止**「铺一个全屏透明窗，只在宠物位置响应点击」这种实现——它会把整个桌面变成点击黑洞。

**2026-10-19 实证补充（见 §2.3.3）**：这条约束是硬的，且现在有反面证据可参照——大肥鱼让角色周围 63% 的透明区不挡点击，靠的是 WPF `AllowsTransparency` → `WS_EX_LAYERED` 分层窗口的**逐像素 alpha 命中**（配合解码侧 `a<8→0` 键控与 `HitTestCore` 的 `alpha>=16` 判定）。这整套在 Tauri/WebView2 上没有对应能力，**别指望"我们照抄它的窗口尺寸公式就行"**：它敢留大片透明留白，我们不敢。由此两条具体改法：宠物窗 = 可见包围盒（α-WebM 素材下 Scale=1 约 175×220，宽高比 ≈0.79 而非正方形）；屏幕钳制按**可见内容**而非窗口矩形（`CompanionEdgeLayout.Clamp` 的思路）。

### 5.2 Win10 大尺寸透明置顶窗黑屏

[issue #15947](https://github.com/tauri-apps/tauri/issues/15947)（2026-08 报告，1440×900 `transparent:true` 桌宠向游戏）：Win10 透明置顶窗黑屏，触发条件是**高频 `set_ignore_cursor_events`** 与最小化时的 DWM 竞争；建议 `noRedirectionBitmap` 或避免频繁切换。

**对策**：

- **不要给尺寸编造硬上限**：#15947 的触发条件是高频 `setIgnoreCursorEvents` 与最小化时的 DWM 竞争，**不是绝对尺寸**——本项目现有便签态本身就是 620×500 的透明窗且运行正常。宠物态真正要约束的是「窗口 = 可见包围盒、不留透明区」（§5.1），尺寸大小是**桌面死区**问题而不是黑屏问题；
- 缩回/展开**不要用「toggle 穿透 + 轮询光标」实现**，改用 Tauri 窗口的 `pointerenter` / `pointerleave`（移开缩回只需要知道「鼠标离开了窗口」，窗口本身就能报这个事件）；
- 若必须轮询 `cursorPosition()`，只做**只读轮询**（约 100–200ms），绝不同步 toggle 穿透状态。

相关同类坑：

- [issue #11088](https://github.com/tauri-apps/tauri/issues/11088) Win10 无边框窗**顶部一条黑线** —— 与本项目现有的 `decorations:false` 直接相关，现已用于便签，可参照现有表现；
- [issue #14515](https://github.com/tauri-apps/tauri/issues/14515) 创建「隐藏 + 透明 + 无边框 + 无阴影」窗后首次显示背景异常 —— 若走双窗方案会撞上。

### 5.3 销毁重建 Milkdown 的代价

AGENTS.md 已记录：Crepe 初始化会回调一次 `markdownUpdated`，`src/components/NoteEditor.tsx:48` 的 `isFirstUpdate` 用于跳过这次伪保存（`NoteEditor.tsx:65-66`），否则会刷新 `updated_at` 并把委托标题改成当天。

**对策**：形态切换**只折叠、不卸载**。收起时把编辑器容器 `visibility:hidden` / `height:0` 但保留 DOM（或 `display:none` 前先确认状态已保存）；绝不为省内存去 `close()` webview。

### 5.4 `window-state` 会记住「宠物态」的尺寸

插件在应用退出时保存所有窗口状态并在下次恢复。本项目当前的 flags 是 `StateFlags::all() & !VISIBLE`（`src-tauri/src/lib.rs:1836-1838`）——**SIZE / POSITION / MAXIMIZED / DECORATIONS / FULLSCREEN 全都在存**，只排除了可见性。所以若退出时恰好处于缩小的宠物态，**下次启动就是一个宠物态尺寸的小窗**，还会被 `tauri.conf.json` 的 `minWidth:340 / minHeight:300` 夹成一个四不像。

**对策**：把 SIZE 与 POSITION 也从 flags 里剔除（`& !StateFlags::SIZE & !StateFlags::POSITION`），形态与几何完全由我们自己持久化（`pet` 与 `note` 各存一份 size/position），启动后按「上次形态」显式落位。这条与 §4.4 的 BongoCat #628（开机自启后记不住关机前位置）是同一类问题，一并解决。

### 5.5 开机自启在 debug 下被拒

AGENTS.md：自启直接写 `HKCU\...\Run`，`cfg(debug_assertions)` 下被拒绝。「桌宠常驻 + 开机出现」的行为**只能在发布版验证**，`npm run tauri dev` 里测不到。

### 5.6 数据目录是真实的

`npm run tauri dev` 与正式版共用 `%APPDATA%\com.liurr.lightweight-sticky-notes\`，dev 起来会**真实结算并改写**当天委托与余额。做交互联调前先备份该目录。

## 6. 架构方案对比

| 维度                       | **A. 同一窗口两态**（推荐）                                            | B. 独立宠物窗 + 便签窗                                                                                                    |
| -------------------------- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 权限改动                   | 无（§4.2 所需权限已齐）                                                | 需新增 `capabilities/pet.json` + 把新 label 加进 windows 数组                                                             |
| 穿透/遮挡风险              | 低（窗口尺寸始终等于内容尺寸）                                         | 高（两窗重叠、透明区叠加，正是 [#308](https://github.com/dsh-tauri-desk/deepseek-harness-desktop/issues/308) 翻车的原因） |
| 编辑器存活                 | 天然存活，只折叠 CSS                                                   | 需处理便签窗 hide/show 与状态同步                                                                                         |
| Win10 黑屏风险             | 小（无高频穿透 toggle）                                                | 大（多窗 + 频繁显隐）                                                                                                     |
| 「宠物常驻、面板临时」语义 | 需要在同一窗内切换 alwaysOnTop（面板态可考虑取消置顶以便被其他窗遮挡） | 天然分离                                                                                                                  |
| 内存                       | 单 webview                                                             | 每多一个 webview 多一份渲染进程开销                                                                                       |
| 实现工作量                 | **小**，可当天出 spike                                                 | 中—大                                                                                                                     |

**结论：走 A。** B 只在「宠物需要在便签打开时继续在桌面游走」成为硬需求时才值得引入。

### 6.1 方案 A 的关键时序（伪代码）

```
宠物态  窗口 = 可见包围盒（色块期 120×150 / α-WebM 约 175×220），alwaysOnTop=true，内容为 <video> 或精灵表
  │ 单击（pointerdown 且非拖拽；拖拽走 startDragging，需区分二者）
  ▼
展开中  ① 先 set_size(noteW×noteH) + set_position（按 monitor 工作区夹取，防止超出屏幕）
        ② 再跑 CSS 动画（opacity/scale/height），避免每帧 resize 触发 webview 重绘
  ▼
便签态  复用现有 NoteEditor 组件，编辑器 DOM 一直存活
  │ pointerleave + 宽限期（可配：关 / 立即 / 0.5s / 2s，默认 0.5s）
  │   ├─ 若期间 pointerenter 回到窗口 → 取消收起
  │   └─ 若编辑器 hasFocus() / 正在输入 / 有未保存改动 → **禁止收起**（否则选不了字、丢内容）
  ▼
收起中  ① 先跑 CSS 折叠动画 ② 动画结束再 set_size(宠物盒) + set_position（回到原锚点：宠物应停在面板的哪个角要想清楚）
```

补充要点：

- **`minWidth/minHeight` 会挡住缩小**：`tauri.conf.json` 现在是 `minWidth:340 / minHeight:300`，`set_size` 到 175×220 会被夹住。缩回前必须先 `setMinSize(null)`（或极小值），展开后再恢复便签态下限——这需要 `core:window:allow-set-min-size`。

- **单击 vs 拖拽**：现有标题栏已在用 `data-tauri-drag-region`（`src/components/TitleBar.tsx:78`，并在 `:80` 判断 `e.target` 是否就是拖拽区本身，双击切最大化）。宠物态若整窗都是拖拽区，`pointerdown` 会直接启动拖拽、收不到正常的 click——需要在 `mousedown` 记录屏幕坐标、`mouseup` 时位移小于阈值才判定为「单击展开」（LingoPet / 小美同学都是这套区分逻辑）。
- **锚点一致性**：面板以宠物的哪个角为原点展开（右下宠 → 左上展开，避免超出屏幕）需要按所在屏幕区域动态选择，配合 `availableMonitors()` / `monitorFromPoint()`。
- **移开缩回必须可关**：DeskBox 把它做成可选项是对的——写东西时鼠标不可避免地会滑出窗口。
